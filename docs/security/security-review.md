# مرور امنیتی نسخه نهایی

## مرزهای اعتماد

- هویت کاربر از ChatGPT گرفته می‌شود، اما نقش مدیر و تخفیف بوعلی از state سمت سرور تعیین می‌شوند.
- درخواست‌های تغییر وضعیت، پرداخت، رزرو و فایل همگی مجوز مالکیت/نقش را سمت سرور بررسی می‌کنند.
- محیط production هیچ مسیر synthetic settlement ندارد.

## کنترل‌های پیاده‌شده

- validation و محدودسازی متن، تعداد، تاریخ، MIME و اندازه فایل.
- queryهای D1 پارامتری و بدون الحاق ورودی کاربر.
- رزرو ظرفیت با `INSERT ... SELECT` و شرط ظرفیت انجام می‌شود تا oversell عادی رخ ندهد.
- idempotency برای ساخت رزرو و شروع پرداخت.
- snapshot قیمت و source reference برای قابلیت ممیزی.
- تاریخچه رزرو، audit event، payment event و checklist تحویل/بازگشت.
- فایل‌ها در R2 خصوصی‌اند و دانلود مالکیت/مدیر را کنترل می‌کند.
- پیام خطای عمومی فاقد stack، SQL و اطلاعات حساس است.

## ریسک‌های باقیمانده و تصمیم عملیاتی

- provider پرداخت و اعلان واقعی هنوز credential محیط production می‌خواهد؛ تا تنظیم آن‌ها، fail-closed است.
- ردیف‌های اکسل در مرز ۶، ۱۰ و ۲۰ همپوشانی دارند. قانون نسخه حاضر «اولین ردیف مطابق ترتیب منبع» است و با تست قفل شده؛ مالک محصول باید هر تغییر سیاست را نسخه‌گذاری کند.
- job حذف نهایی فایل‌های منقضی باید در scheduler زیرساخت فعال شود.
